# Session: LocalCode AFM Integration

**Date:** 2026-06-11
**Time:** 19:52

## Goal
Integrate Apple Foundation Models (AFM) with OpenCode as a local AI provider for CLI tooling.

## What Works
1. **AFM Server** (`start-afm-server.sh`) - Bun HTTP server that wraps the Swift AFM helper
   - Implements OpenAI-compatible API (`/v1/models`, `/v1/chat/completions`)
   - Supports both streaming and non-streaming responses
   - Runs on port 8080

2. **Swift AFM Helper** (`LocalCode/Sources/afmhelper/main.swift`)
   - Uses `SystemLanguageModel.default` for on-device AI
   - Returns JSON with `command` field (bash suggestion) and `content` field (description)
   - CLI: `afmhelper "<user message>"`

3. **OpenCode Provider Config**
   - Added to `~/.config/opencode/opencode.json`:
   ```json
   "provider": {
     "localcode-afm": {
       "npm": "@ai-sdk/openai-compatible",
       "name": "LocalCode AFM",
       "options": {
         "baseURL": "http://localhost:8080/v1"
       },
       "models": {
         "afm": { "name": "Apple Foundation Models" }
       }
     }
   }
   ```

4. **End-to-end flow**
   - AFM server → OpenCode → Command suggestion displayed in chat
   - Works via curl and in OpenCode UI

## What's Working (Partial)
- AFM provider appears in OpenCode `/models` list and can be selected
- AFM returns command suggestions in OpenCode chat
- Command approval UI (approve/reject buttons) not appearing - shows as plain text instead

## What's NOT Working
- Command approval UI in OpenCode - responses show as plain text, not as a command block with approve/reject
- Local fork not needed - global opencode with provider config works

```bash
cd /Users/christophercarvalho/localcode

```

### Test AFM Server
```bash
# List models
curl http://localhost:8080/v1/models

# Chat completion
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"afm","messages":[{"role":"user","content":"hello"}]}'

# Streaming
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"afm","messages":[{"role":"user","content":"hello"}],"stream":true}'
```

### Run OpenCode with AFM
```bash
# Provider config in ~/.config/opencode/opencode.json
opencode
```

## Key Learnings
- OpenCode uses `provider` (singular), not `providers` (plural) in config
- `npm` field specifies the AI SDK package (e.g., `@ai-sdk/openai-compatible`)
- Global opencode works with provider config - no need for local fork
- AFM needs a task to suggest a command - conversational "hello" works but gives generic response
