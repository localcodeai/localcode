# Session Notes - 2026-06-11

## What's Working
- AFM server with OpenAI-compatible API at http://localhost:8080/v1
- Tool call responses with `bash` tool for command execution
- SSE streaming support (2 chunks: role + tool_calls)
- OpenCode provider config using `@ai-sdk/openai-compatible`
- Extracts user message from OpenCode's system prompt

## Test Commands That Work
```bash
# Server running
curl http://localhost:8080/v1/models

# Direct AFM test
cd LocalCode/Sources/afmhelper && ./afmhelper "list all python files"
# Returns: {"command":"find . -name \"*.py\"","content":"..."}

# Server test
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"afm","messages":[{"role":"user","content":"list all python files"}]}'
# Returns clean tool_calls
```

## Known Limitations / QA Failing
- OpenCode streaming shows text streaming down instead of command approval dialog
- AFM outputs partial commands when receiving OpenCode's full system prompt
- curl test works fine; OpenCode shows wrong output
- Non-streaming returns correct tool_calls; streaming in OpenCode shows extraneous text

## Next Steps
- Debug why OpenCode streaming shows content chars instead of just tool_call
- Investigate why AFM behaves differently with OpenCode vs direct curl
- Consider disabling streaming or fixing SSE format for OpenCode compatibility

## Architecture
- `start-afm-server.sh`: Bun HTTP server wrapping Swift AFM helper
- `LocalCode/Sources/afmhelper/main.swift`: Apple FoundationModels integration
- Provider config: `~/.config/opencode/opencode.json`
- No fork needed - uses global OpenCode with provider config
